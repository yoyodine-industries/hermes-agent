7. What deploying PR #21 changes

Merging PR #21 registers three routes on the gateway and adds a dedicated message API on top of the existing queue and drainer — it does not replace them:

  • POST /v1/messages → _handle_message_send → _handle_bot_send (converges on the same admission + queue).
  • GET /v1/messages/{delivery_id} → status read from the ledger.
  • POST /v1/messages/{delivery_id}/ack → receiver ack, adding a new acknowledged stage the live path lacks.
  • Auth: _check_hub_auth validates a Bearer token against the gateway root API_SERVER_KEY (branch-only; the term "hub" is the rejected prose name).

The missing call on live today is exactly the /v1/messages route registration at api_server.py:1571-1573 — present only on the unmerged branch.
